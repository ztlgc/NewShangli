# 回收站重构

当前实现采用第二版紧凑分组列表，并按用户确认的交互改为左滑操作，不使用点按详情弹层。`recycle-bin-redesign.png` 是早期提案，仅供历史参考。

`implemented-browse.png`、`implemented-swipe.png`、`implemented-selection.png`、`implemented-confirmation.png` 和 `implemented-dark-swipe.png` 是实际 Flutter 页面在隔离内存数据库中渲染的示例截图。

## 页面行为

- 保留收支记录、联系人两个分类，各自显示未筛选总数。
- 收支记录支持搜索姓名、事由、原账簿；联系人支持搜索姓名、关系、电话。
- 按删除时间倒序，分为今天、昨天及具体日期，同一天的条目合并为一张分组卡片并显示数量；没有自动清理期限。
- 分类与搜索固定在顶部。姓名与金额优先显示，次行展示事由和删除时刻，底行保留原账簿与礼金日期；联系人展示关系、电话与已删除关联记录数量。
- 每条记录和联系人均可向左滑动，露出「恢复」「删除」按钮。滑动到尽头也不执行写入，必须点击按钮；「删除」表示彻底删除，点击后确认对象、金额及关联影响。
- 同一时间只展开一条。右滑、点按其他位置、纵向滚动、修改搜索、切换分类或进入管理时收起。系统返回先收起已展开的操作区，再返回上页。
- 点击「管理」或长按条目进入多选。全选只选择当前分类的搜索结果；修改搜索条件清除选择，切换分类退出选择模式，系统返回优先退出选择模式。选择模式下关闭左滑，底部固定批量恢复与彻底删除操作。
- 屏幕阅读器可通过条目的「显示恢复和删除按钮」语义动作展开操作区。
- 恢复与彻底删除均接入现有编辑保护；操作进行中阻止重复提交。
- 批量写入使用数据库事务。失败保留选择以便重试，不显示成功提示。

## 关联规则

- 恢复记录：如果对应联系人已删除，先确认同时恢复联系人，只恢复选中的记录。
- 恢复联系人：先说明只恢复联系人，关联记录仍留在回收站。
- 彻底删除记录：确认对象、金额、数量，并说明联系人保留。
- 彻底删除联系人：列出关联记录总数，包括仍处于正常状态的记录数量，并说明同时删除联系人关系。确认后再次检查关联记录范围，变化时取消整批写入，提示重新确认。
