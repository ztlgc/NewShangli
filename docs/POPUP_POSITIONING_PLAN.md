# 弹窗定位调整方案

## 交互规则

- 小型操作菜单和简单选项在触发控件附近显示。优先在控件下方展开；下方不足时向上展开，左右位置限制在屏幕安全区内。横屏键盘等导致上下空间都不足时，允许弹窗与触发控件位置重叠，以保证标题和选项可见，长列表内部滚动。
- 账簿、联系人、事由等需要搜索、管理或浏览较长列表的选择面板，以及日期选择、编辑表单等较大内容，固定在可用屏幕中央显示。
- 确认、警告和输入对话框居中显示，横屏也保持一致。
- 弹窗类别由功能入口指定，不以当前选项数量决定，避免同一功能随数据量变化而改变位置。
- 屏幕边缘保留 16 逻辑像素间距，避让系统安全区与软键盘。长列表在弹窗内部滚动；大面板最大宽度 560，小菜单最大宽度 320，最大高度不超过可用区域的 90%。
- 使用淡入和轻微缩放，移除从底部滑入及拖拽手柄。系统减少动态效果开启时取消缩放。
- 保留点击外部、关闭按钮、系统返回键的取消行为，保留选择返回值、已选标识、异步操作保护和原有编辑权限校验。

## 实现步骤

1. 增加共享弹窗路由与定位布局，在打开时获取触发控件矩形并完成边界约束。
2. 调整现有 `AppBottomSheet` 兼容入口：标准内容和自定义复杂内容默认居中，简单选择器可传入触发控件位置以就近显示。
3. 为小菜单入口提供局部 `BuildContext` 作为锚点；较大面板保持居中，清理底部弹层专用外观和键盘补偿。
4. 移除 `AppDialog` 横屏时切换到底部弹层的逻辑，使确认与输入对话框始终居中。
5. 更新设计规范，并通过组件定位测试、实际页面交互测试、静态分析和现有回归测试验证。

## 验证重点

- 顶部、底部、左右边缘触发时的位置及完整可见性。
- 长选项列表的滚动和选择返回值。
- 记录新增/详情的账簿选择居中，选择后保留原有更新行为。
- 窄屏、横屏、较大文字、键盘弹出时的约束与滚动。
- 关闭按钮、点击遮罩、系统返回键均能正常关闭，再次打开无残留状态。
- 真实 Android 设备的键盘动画与触控体验需要另行真机确认，测试结果不等同于真机验证。

## 实施与验证结果（2026-11-05）

- 已新增 `AppPopup` 共享定位路由；`AppBottomSheet` 原调用入口转为浮动面板，不再使用底部弹层路由。
- 账簿选择、联系人/事由选择、账簿内新增记录、导入字段匹配/预览/详情/历史、月份选择、类型编辑和 WebDAV 配置均居中。原有农历日期选择器已是居中布局，继续保留。
- 账簿详情更多菜单、日期范围、导入模板、字段匹配内的列名选择及统计年份选择已接入局部触发控件锚点；联系人关系类型选择按反馈改为居中显示。备份频率保留原有禁用状态，未启用自动备份功能。
- `AppDialog` 确认/输入/提示框横屏也保持居中；自定义面板移除拖拽手柄及重复的安全区/键盘留白。类型编辑与 WebDAV 表单支持可见区域内滚动。
- 完整 Flutter 测试回归：389 项通过、1 项跳过。最终补充横屏键盘与大字体的菜单布局保护后，受影响组件和页面的 92 项测试全部通过。
