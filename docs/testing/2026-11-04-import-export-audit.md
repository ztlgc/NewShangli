## 已确认问题

### D01：普通 Excel 含附件路径会使再次导入失败（优先修复）

- 复现：创建带本地附件的礼金 → 在数据导出中选择 Excel（界面 `includeImages=false`）→ 将原样 XLSX 导入新库。
- 预期：业务行能导入；不携图的格式应有一致的附件处理约定，至少不应因自身输出的附件路径而使整批业务数据导入中断。
- 实际：任务 `failed`，记录没有提交。XLSX 写入源设备的绝对附件路径，导入器只从媒体 ZIP 查找该引用，找不到便抛异常。
- 定位：`lib/export/data_export_service.dart:248`；`lib/import/data_import_service.dart:1132`。
- 证据：IE20。ZIP 携图往返 IE08 对照通过。当前文档说明 Excel 保留原路径，但没有提供原样重新导入这些引用的可用路径；这不是声称 Excel 本身应包含图片。

### D02：两种官方模板都会创建两个“张三”

- 复现：不编辑生成的 CSV 或 XLSX 模板，直接预览并导入。
- 实际：任务完成且无失败行，但生成 2 个联系人。联系人示例行带手机号，礼金示例行手机号为空；姓名+手机号匹配将它们识别为不同联系人，礼金关联到另一个无手机号的“张三”。
- 定位：`lib/import/data_import_template_service.dart:30`、`:44`；`lib/import/data_import_service.dart:1016`、`:1165`。
- 证据：IE01 两个独立失败。预期 1，实际 2。

### D03：自定义附件字段映射静默丢附件

- 复现：把“附件1名称”列改为“票据”，字段匹配中设置“附件1名称 → 票据”，选择包含实际附件的 ZIP。
- 实际：任务完成，但数据库 `attachments=null`。解析器扫描原始列名寻找 `附件N名称`，映射后的标准字段没有参与枚举。
- 定位：`lib/import/data_import_service.dart:1121`。
- 证据：IE24。

### D04：CSV 联系人头像被忽略

- 复现：CSV 联系人列表填写“头像文件名”，同时提供含相应媒体路径的 ZIP。
- 实际：任务完成但 `avatar_uri=null`。CSV 联系人分支只调用基础解析；读取并保存头像的逻辑只在双工作表 Excel 分支执行。
- 定位：`lib/import/data_import_service.dart:794` 与 `:869`。
- 证据：IE23，Excel/ZIP 头像往返 IE08 为通过对照。

### D05：错误日志并发写入会损坏或缺行

- 复现：80 行金额为 -1 的 CSV，导入完成后立即以 UTF-8 读取日志并核验每个源行号。
- 实际：`failedRows=80`，但日志读取抛出 `FileSystemException: Failed to decode data using encoding 'utf-8'`。在多轮独立执行中复现。
- 原因：多个 `unawaited(_onLog(...))` 同时执行文件追加；没有顺序写入和完成前排空机制。
- 定位：`lib/import/data_import_service.dart:359`、`:941`。
- 证据：IE27；最初 IE04 同样发现日志 UTF-8 损坏，后将日志完整性单独拆为 IE27 验证。

### D06：同名媒体歧义会静默绑定其中一个文件

- 复现：ZIP 中放入 `media/attachments/a/photo.png` 与 `media/attachments/b/photo.png`，二者字节不同；表格只写 `photo.png`。
- 预期：要求精确 ZIP 相对路径，或显式提示歧义供确认。
- 实际：任务直接完成，根据目录/条目顺序选第一个候选，不报告歧义；无法保证附件关联正确。
- 定位：`lib/import/data_import_service.dart:1291`、`:1301`。
- 证据：IE36；导出器生成精确路径的 IE08 通过，因此该问题针对外部导入中的歧义引用。

### D07：缺失头像被同时计为成功与跳过

- 复现：一个 Excel 联系人行引用不存在的头像。
- 实际：`processedRows=1`，`successRows=1`，`skippedRows=1`，`failedRows=0`；三个结果分类之和为 2。联系人实际写入成功。
- 定位：`lib/import/data_import_service.dart:679`、`:906`。
- 证据：IE29。缺媒体应作为该成功行的警告，或明确采用另一种统计模型，当前“跳过行”与成功行重复。

### D08：往返会裁剪文本边缘空白

- 复现：联系人/记录备注为 `  原样备注\n`，导出 XLSX 再导入。
- 实际：联系人备注变为去除首尾空白的文本；记录备注解析也执行 trim。值发生变化，无法逐字节还原文本。
- 定位：`lib/import/data_import_service.dart:675`、`:722`、`:1096`。
- 证据：IE21。此为低影响保真问题，不能与丢记录问题等量看待。

### D09：批次回滚不清理已经保存的媒体

- 复现：双工作表 Excel 中联系人姓名超过数据库 32 字约束，同时提供有效头像 ZIP。
- 实际：任务失败且联系人表为空，但 `media/avatars/avatar_*.png` 已落盘并保留。
- 原因：媒体保存发生在数据库事务提交之前，数据库回退没有对应文件清理。
- 定位：`lib/import/data_import_service.dart:911` 与 `:1182`。
- 证据：IE25。影响是孤儿文件与后续备份体积增长，不是既有联系人被破坏。

### D10：无默认账簿的服务调用会覆盖记录发生时间（边界问题）

- 复现：目标有一个非默认账簿、没有默认账簿；服务层导入带新默认账簿 ID 的两条记录，原发生时间相差 10 天。
- 实际：两条记录时间都变成待创建账簿的 `bookTime`。同金额/人员/事由时还可能触发错误的重复判定；测试选择保留重复以便独立观察两条时间。
- 定位：`lib/import/data_import_service.dart:1062`。
- 证据：IE22。**常规数据导入页面先执行 DefaultBookService 保证默认账簿存在，因此此问题不作为正常界面流程中的必现缺陷。** 常规跨库 ID 重映射及时间保留 IE38 已通过。

## 导出范围的解释

业务导出当前只包含有效联系人、有效礼金及记录所引用的部分账簿字段，按日期/账簿范围输出。联系人关系类型值可以保留，但联系人之间的关系图、事由/关系字典、空账簿、账簿主题/描述/图片、回收站、完整修改时间与导入任务等，不属于该 XLSX/ZIP 业务交换格式的完整数据库还原能力。不能使用业务导出替代完整备份，也不把这些有意的格式边界逐项计为缺陷。

完整数据库、媒体、回收站、附加备注和 WebDAV 的独立测试结果见同目录 `2026-11-04-backup-restore-audit.md`，总览见 `2026-11-04-data-integrity-audit.md`。
