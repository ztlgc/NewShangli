## 结论

本轮完成本地数据闭环的主要风险整改，全量 Flutter 测试 136 项通过。隔离测试已覆盖业务归属、精确金额、重复导入决策、导入失败重试、Excel/附件往返、WAL 快照异地恢复、重复恢复、恢复失败回滚和启动恢复日志。

这不等于正式发布验收通过。真实云端/RLS、设备文件选择与生命周期、断电和磁盘不足尚未验证；自动备份尚未实现后台调度。云端表级同步仍不是完整备份，也不能声称全链路原子同步。

## 业务决定与当前合同

- 用户已确认：联系人全局共享；personId 为身份，同名但不同 ID 的对象不合并。person.bookId 仅保留创建来源信息，不再约束联系人生命周期。
- 用户已确认：疑似重复礼金由用户逐条选择跳过或保留。相同记录 ID 或相同账本、联系人、日期、金额、方向、事由触发确认；选择保留时必要情况下生成新 ID。这是人工确认策略，不是永久禁止重复。
- 无联系人 ID 时，仅唯一的姓名+电话匹配可复用；多个匹配对象会使该行失败并写日志，要求提供 ID，避免随意归属。
- 用户已确认：修改非默认账本日期与事由在同一事务中更新其全部记录，包含软删除记录。默认账本保留逐条记录的日期与事由。
- 金额使用整数分，合法范围 1..99999999999999 分。导入拒绝零、负数、非有限值、科学计数法、超过两位小数和不合法日期；不静默四舍五入。
- 应用未发布：不提供旧版备份兼容承诺。数据库版本为 14；保留 13→14 安全变更，其他旧版本拒绝打开且不执行旧有清库逻辑。
- 云恢复语义是本轮采用的默认方案，尚未获得单独明确确认：ZIP 覆盖恢复；表级同步按 ID 合并并保留本地独有数据，账本/联系人/礼金比较更新时间。

## 导入、导出与备份的精确边界

导入按批次（最多 2000 个待处理条目）提交，不是整文件事务。每批关联对象、账本、记录和检查点一起提交；后续批次失败保留已提交批次，可从检查点重试。暂停/取消在服务确认完成当前工作后结束。成功计数包含创建的联系人和礼金，不能直接当作礼金记录数。校验失败行会记录错误，不保证整文件一条错误就全部回滚；粘贴入口在解析文本阶段全部通过才提交。

业务导出用于交换当前范围内联系人与礼金，不包括完整删除状态、应用偏好、所有关联表或全部账本附加信息，不能替代备份。附件仅在选择包含图片时携带；不含媒体的备份恢复时清空媒体引用。带媒体备份缺少引用文件会拒绝恢复，避免静默产生失效附件。

备份通过 SQLite VACUUM INTO 生成一致数据库快照，包含数据库中的八张表及可选媒体；manifest 包含格式/数据库版本、数据库 SHA256 和文件信息。不会备份登录会话、WebDAV 凭据或全部 SharedPreferences 设置。恢复会取消不可跨机器继续的导入任务。

恢复先检查并暂存，再保存原数据库/媒体到隔离保护目录，写入恢复日志后替换；失败回退，启动时检测未完成日志并回退。事务保护和日志可降低中断风险，但尚未验证突然断电时的文件系统持久化顺序。数据库校验不是对任意恶意 SQLite schema 的完整沙箱审计。

4. **资源边界**：当前 ZIP 为内存处理，中央目录预检限制并非恶意伪造解压大小时的硬内存上限；大文件性能、流式/后台解析与更严格资源隔离待完善。

6. **自动备份**：当前明确未实现后台调度；需要真正的平台调度、重试与状态验证后才可启用。
7. **额外业务确认（不阻塞本轮）**：无 ID 的同名同电话联系人是否需要人工选择、是否允许零礼金、完整备份是否应携带应用偏好。当前分别采用唯一匹配复用、金额严格正数、仅业务库+可选媒体的规则。
